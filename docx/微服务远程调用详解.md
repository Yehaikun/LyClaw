# LyClaw 微服务远程调用详解

---

# 第一课：整体架构概览

## 1.1 项目有哪些微服务？

`docker-compose.yml` 定义了 **7 个微服务 + 1 个注册中心**：

| 服务名 | 端口 | 职责 |
|--------|------|------|
| `lyclaw-gateway` | 8080 | API 网关，所有外部请求的入口 |
| `lyclaw-orchestration-service` | 8081 | 编排服务，AI 流水线的"大脑" |
| `lyclaw-memory-service` | 8082 | 记忆服务，存储和检索上下文 |
| `lyclaw-plan-service` | 8083 | 规划服务，任务分解 |
| `lyclaw-action-service` | 8084 | 动作服务，执行工具调用 |
| `lyclaw-reflect-service` | 8085 | 反思服务，评估执行结果 |
| `lyclaw-protocol-service` | 8086 | 协议服务，MCP/A2A 协议 |
| `nacos` | 8848 | 服务注册中心 |

## 1.2 两种远程调用路径

```
用户请求 → [浏览器] → Gateway(8080) → Orchestrator(8081) → Feign → Memory(8082)
                                                          → Feign → Plan(8083)
                                                          → Feign → Action(8084)
                                                          → Feign → Reflect(8085)
```

- **南北向流量**（Gateway → 内部服务）：外部请求通过网关路由到内部服务
- **东西向流量**（Orchestrator → 其他服务）：服务之间通过 Feign 互相调用

## 1.3 核心技术栈

- **Nacos**：服务注册与发现（相当于电话簿，每个服务启动时在上面登记自己的地址）
- **Spring Cloud Gateway**：API 网关（统一入口，路由转发）
- **Spring Cloud OpenFeign**：声明式 HTTP 客户端（服务间调用的核心工具）
- **Spring Cloud LoadBalancer**：客户端负载均衡（从多个实例中选一个）

# 第二课：Nacos 服务注册与发现

## 2.1 bootstrap.yml 配置

文件：`lyclaw-orchestration/src/main/resources/bootstrap.yml`

```yaml
spring:
  application:
    name: lyclaw-orchestration-service
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
        namespace: lyclaw
        group: DEFAULT_GROUP
server:
  port: 8081
```

**逐行解释：**

- **`spring.application.name: lyclaw-orchestration-service`**：服务的"身份证名字"。服务启动时以这个名字向 Nacos 注册。其他服务想调用它时，就用这个名字来查找。**这个名字和后面 Feign 的 `name` 参数必须完全一致。**

- **`server-addr: 127.0.0.1:8848`**：Nacos 的地址。服务启动后会主动连接这个地址，说"我叫 lyclaw-orchestration-service，我的地址是 192.168.x.x:8081"。

- **`namespace: lyclaw`**：命名空间，用于环境隔离。比如 `dev`、`test`、`prod` 三个命名空间，同名服务在不同空间互不影响。

- **`group: DEFAULT_GROUP`**：分组，同一命名空间下的进一步划分。

## 2.2 @EnableDiscoveryClient

```java
@SpringBootApplication(scanBasePackages = "lyjew.com.lyclaw")
@EnableDiscoveryClient    // ← 关键！开启服务注册与发现
@EnableFeignClients(basePackages = "lyjew.com.lyclaw.feign")
public class OrchestrationServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(OrchestrationServiceApplication.class, args);
    }
}
```

**`@EnableDiscoveryClient`**：告诉 Spring Cloud："启动后去 Nacos 注册自己，并且能从 Nacos 发现其他服务"。没有它，服务就是"隐身"的，别人找不到你。

## 2.3 服务注册流程

1. Spring Boot 启动，读取 `bootstrap.yml`
2. 读到 `spring.application.name = lyclaw-orchestration-service`
3. `@EnableDiscoveryClient` 触发：连接 `127.0.0.1:8848` 的 Nacos
4. 向 Nacos 注册：`{ 服务名: "lyclaw-orchestration-service", IP: "192.168.1.5", 端口: 8081 }`
5. 每 5 秒发一次心跳，告诉 Nacos "我还活着"
6. Nacos 超过 15 秒没收到心跳，就把该服务标记为下线

# 第三课：Spring Cloud Gateway 网关路由

## 3.1 路由配置

文件：`lyclaw-gateway/src/main/java/.../GatewayConfig.java`

```java
@Configuration    // ← 告诉 Spring：这是一个配置类，里面的 @Bean 方法会被 Spring 管理
public class GatewayConfig {

    @Bean    // ← 把这个方法的返回值注册为 Spring Bean
    public RouteLocator customRoutes(RouteLocatorBuilder builder) {
        // builder 是 Spring 提供的路由构建器
        return builder.routes()    // ← .routes() 开始构建路由列表
                .route("chat-api", r -> r    // ← 定义一条路由，ID 是 "chat-api"
                        .path("/api/chat", "/api/chat/stream")    // ← 匹配这些路径
                        .uri("lb://lyclaw-orchestration-service")) // ← 转发到这里
                .route("sessions-api", r -> r
                        .path("/api/sessions/**")
                        .uri("lb://lyclaw-orchestration-service"))
                .route("memory-api", r -> r
                        .path("/api/memory/**")
                        .uri("lb://lyclaw-memory-service"))
                .route("plan-api", r -> r
                        .path("/api/plan/**")
                        .uri("lb://lyclaw-plan-service"))
                .route("action-api", r -> r
                        .path("/api/action/**")
                        .uri("lb://lyclaw-action-service"))
                .route("reflect-api", r -> r
                        .path("/api/reflect/**")
                        .uri("lb://lyclaw-reflect-service"))
                .route("protocol-api", r -> r
                        .path("/api/protocol/**")
                        .uri("lb://lyclaw-protocol-service"))
                .build();    // ← .build() 完成构建
    }
}
```

## 3.2 逐行解释 `route("chat-api", r -> ...)`

- **`"chat-api"`**：路由的 ID，随便起，但要唯一，用于日志和调试。
- **`.path("/api/chat", "/api/chat/stream")`**：断言规则，如果请求的 URL 路径是 `/api/chat` 或 `/api/chat/stream`，就匹配这条路由。
- **`.uri("lb://lyclaw-orchestration-service")`**：转发目标。

## 3.3 `lb://` 的含义

`lb` 是 **LoadBalancer（负载均衡）** 的缩写。工作流程：

1. 收到请求 `/api/chat`
2. 看到目标 `lb://lyclaw-orchestration-service`
3. 去 Nacos 问："`lyclaw-orchestration-service` 有哪些实例？"
4. Nacos 回答："有一个实例在 `192.168.1.5:8081`"
5. 如果有多个实例，LoadBalancer 用轮询策略选一个
6. 转发请求到 `http://192.168.1.5:8081/api/chat`

**为什么要用 `lb://` 而不是直接写 `http://localhost:8081`？**

因为微服务可能有多实例、实例会动态上下线、IP 会变。写死 IP 的话，服务挂了请求就全失败。`lb://` 每次都会从 Nacos 获取最新的健康实例列表。

## 3.4 完整路由表

| 路由 ID | 匹配路径 | 转发目标 |
|---------|----------|----------|
| `chat-api` | `/api/chat`, `/api/chat/stream` | `lb://lyclaw-orchestration-service` |
| `sessions-api` | `/api/sessions/**` | `lb://lyclaw-orchestration-service` |
| `memory-api` | `/api/memory/**` | `lb://lyclaw-memory-service` |
| `plan-api` | `/api/plan/**` | `lb://lyclaw-plan-service` |
| `action-api` | `/api/action/**` | `lb://lyclaw-action-service` |
| `reflect-api` | `/api/reflect/**` | `lb://lyclaw-reflect-service` |
| `protocol-api` | `/api/protocol/**` | `lb://lyclaw-protocol-service` |

注意 `/**` 是通配符，匹配多级路径，比如 `/api/memory/retrieve`、`/api/memory/stats` 都会匹配。

# 第四课：OpenFeign 声明式远程调用（核心）

## 4.1 Feign 接口定义

文件：`lyclaw-core/src/main/java/lyjew/com/lyclaw/feign/MemoryFeignClient.java`

```java
package lyjew.com.lyclaw.feign;

import lyjew.com.lyclaw.memory.MemoryQuery;
import lyjew.com.lyclaw.memory.MemoryQueryResult;
import lyjew.com.lyclaw.memory.MemoryStats;
import lyjew.com.lyclaw.memory.PerceptionData;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

@FeignClient(name = "lyclaw-memory-service", path = "/api/memory")
public interface MemoryFeignClient {

    @PostMapping("/retrieve")
    MemoryQueryResult retrieve(@RequestBody MemoryQuery query);

    @PostMapping("/ingest")
    Map<String, Object> ingest(@RequestBody PerceptionData data,
                               @RequestParam("sessionId") String sessionId,
                               @RequestParam(value = "userId", required = false, defaultValue = "default") String userId);

    @PostMapping("/consolidate")
    Map<String, Object> consolidate(@RequestParam("userId") String userId, @RequestParam("sessionId") String sessionId);

    @GetMapping("/stats")
    MemoryStats getStats();
}
```

## 4.2 `@FeignClient` 注解 — 逐字拆解

```java
@FeignClient(name = "lyclaw-memory-service", path = "/api/memory")
```

这是一个**声明式 HTTP 客户端**。你只需要定义接口，Spring 会自动生成实现类。

### `name = "lyclaw-memory-service"`

Feign 注解中**最重要的参数**。工作流程：

1. Spring 启动时，Feign 框架扫描到这个接口
2. 看到 `name = "lyclaw-memory-service"`
3. 去 Nacos 问："谁叫 `lyclaw-memory-service`？"
4. Nacos 返回实例列表，比如 `192.168.1.6:8082`
5. Feign 创建一个**动态代理对象**，注入到 Spring 容器中
6. 当你调用 `memoryFeignClient.retrieve(query)` 时，代理对象自动把调用转成 HTTP 请求发到 `192.168.1.6:8082`

**关键点：`name` 的值必须和 `bootstrap.yml` 中 `spring.application.name` 完全一致。**

### `path = "/api/memory"`

**路径前缀**。定义之后，这个接口里所有方法的路径前面都会自动加上 `/api/memory`：

- `@PostMapping("/retrieve")` → 实际请求路径 = `/api/memory` + `/retrieve` = **`/api/memory/retrieve`**
- `@GetMapping("/stats")` → 实际请求路径 = `/api/memory` + `/stats` = **`/api/memory/stats`**

## 4.3 `@PostMapping` 和 `@RequestBody`

```java
@PostMapping("/retrieve")
MemoryQueryResult retrieve(@RequestBody MemoryQuery query);
```

- **`@PostMapping("/retrieve")`**：声明 HTTP POST 请求，路径为 `/retrieve`，结合 `path` 最终为 `POST /api/memory/retrieve`
- **`@RequestBody MemoryQuery query`**：把方法参数 `query` 序列化为 JSON，放在 HTTP 请求 Body 里
- **`MemoryQueryResult` 返回值**：HTTP 响应的 JSON Body 会自动反序列化为 `MemoryQueryResult` 对象

**实际发送的 HTTP 请求：**
```
POST /api/memory/retrieve HTTP/1.1
Host: 192.168.1.6:8082
Content-Type: application/json

{"queryText":"你好","topK":10}
```

## 4.4 `@RequestParam` — 两种写法对比

```java
@PostMapping("/ingest")
Map<String, Object> ingest(@RequestBody PerceptionData data,          // ← JSON Body
                           @RequestParam("sessionId") String sessionId,  // ← URL 参数
                           @RequestParam(value = "userId", required = false, defaultValue = "default") String userId);
```

- **`@RequestBody`**：数据放在 HTTP Body 里，JSON 格式，适合复杂对象
- **`@RequestParam("sessionId")`**：数据放在 URL 后面，比如 `?sessionId=abc123`，适合简单值
- **`@RequestParam(value = "userId", required = false, defaultValue = "default")`**：
  - `value = "userId"` — URL 参数名叫 `userId`
  - `required = false` — 这个参数不是必传的，不传也不会报错
  - `defaultValue = "default"` — 如果不传，默认值是 `"default"`

**实际发送的 HTTP 请求：**
```
POST /api/memory/ingest?sessionId=abc123&userId=default HTTP/1.1
Host: 192.168.1.6:8082
Content-Type: application/json

{"role":"assistant","content":"...","timestamp":1715432100}
```

## 4.5 `@GetMapping`

```java
@GetMapping("/stats")
MemoryStats getStats();
```

GET 请求没有 Body，参数（如果有）只能用 `@RequestParam` 放在 URL 上。

## 4.6 Feign 的底层原理 — JDK 动态代理

`MemoryFeignClient` 明明只是一个 **interface**，没有实现类，为什么可以直接调用？

答案是 **JDK 动态代理**。Spring 在启动时做了这些事：

```
1. @EnableFeignClients 扫描 "lyjew.com.lyclaw.feign" 包
2. 找到 MemoryFeignClient 接口
3. 读取 @FeignClient(name = "lyclaw-memory-service", path = "/api/memory")
4. 使用 JDK Proxy.newProxyInstance() 创建一个代理对象
5. 注入到 Spring 容器（类型是 MemoryFeignClient）
6. 当代码调用 memoryFeignClient.retrieve(query) 时：
   a. 代理拦截方法调用
   b. 从 @PostMapping 获取路径 "/retrieve"，拼接 path 得到 "/api/memory/retrieve"
   c. 从 @RequestBody 获取参数，序列化为 JSON
   d. 根据 name 去 Nacos 查找 "lyclaw-memory-service" 的实例
   e. LoadBalancer 从实例列表里选一个
   f. 发送 HTTP POST 请求到选中的实例
   g. 收到响应，反序列化为 MemoryQueryResult
   h. 返回给调用者
```

## 4.7 `@EnableFeignClients` — 总开关

```java
@SpringBootApplication(scanBasePackages = "lyjew.com.lyclaw")
@EnableDiscoveryClient
@EnableFeignClients(basePackages = "lyjew.com.lyclaw.feign")  // ← 这一行
public class OrchestrationServiceApplication {
```

- **`@EnableFeignClients`**：告诉 Spring "去扫描指定包下所有带 `@FeignClient` 注解的接口，为它们生成代理对象"
- **`basePackages = "lyjew.com.lyclaw.feign"`**：扫描范围

没有这一行，`@FeignClient` 注解就只是注释，Feign 不会为它生成代理。

## 4.8 五个 Feign 接口一览

| 接口 | `name` | `path` | 目标服务 |
|------|--------|--------|----------|
| `MemoryFeignClient` | `lyclaw-memory-service` | `/api/memory` | memory 服务 :8082 |
| `PlanFeignClient` | `lyclaw-plan-service` | `/api/plan` | plan 服务 :8083 |
| `ActionFeignClient` | `lyclaw-action-service` | `/api/action` | action 服务 :8084 |
| `ReflectFeignClient` | `lyclaw-reflect-service` | `/api/reflect` | reflect 服务 :8085 |
| `ProtocolFeignClient` | `lyclaw-protocol-service` | `/api/protocol` | protocol 服务 :8086 |

# 第五课：调用方 OrchestratorImpl 详解

文件：`lyclaw-orchestration/src/main/java/.../impl/OrchestratorImpl.java`

## 5.1 构造函数注入

```java
@Slf4j          // ← Lombok：自动生成 Logger log
@Service        // ← Spring Service Bean
public class OrchestratorImpl implements Orchestrator {

    private final PlanFeignClient planFeignClient;
    private final ActionFeignClient actionFeignClient;
    private final ReflectFeignClient reflectFeignClient;
    private final MemoryFeignClient memoryFeignClient;
    private final SecurityManager securityManager;
    private final ContentFilter contentFilter;
    private final MetricsCollector metricsCollector;
    private final CollaborationHub collaborationHub;
    private final ModelProvider modelProvider;

    public OrchestratorImpl(PlanFeignClient planFeignClient,     // ← Spring 注入代理对象
                            ActionFeignClient actionFeignClient,
                            ReflectFeignClient reflectFeignClient,
                            MemoryFeignClient memoryFeignClient,
                            SecurityManager securityManager,
                            ContentFilter contentFilter,
                            MetricsCollector metricsCollector,
                            CollaborationHub collaborationHub,
                            ModelProvider modelProvider) {
        this.planFeignClient = planFeignClient;
        this.actionFeignClient = actionFeignClient;
        this.reflectFeignClient = reflectFeignClient;
        this.memoryFeignClient = memoryFeignClient;
        this.securityManager = securityManager;
        this.contentFilter = contentFilter;
        this.metricsCollector = metricsCollector;
        this.collaborationHub = collaborationHub;
        this.modelProvider = modelProvider;
    }
```

**逐变量解释：**

- **`PlanFeignClient planFeignClient`**：Spring 注入的不是 interface，而是 Feign 框架用 JDK 动态代理生成的**代理对象**。类型是 `Proxy($Proxy123)`，实现了 `PlanFeignClient` 接口。调用 `planFeignClient.plan(...)` 时，代理对象在背后发 HTTP 请求。
- **`private final`**：`final` 表示一旦构造函数赋值后就不能再改，保证线程安全。Spring 推荐用构造器注入而不是 `@Autowired` 字段注入。
- **`SecurityManager`、`ContentFilter`**：安全相关组件。
- **`MetricsCollector`**：监控指标收集器，记录每个阶段的耗时。
- **`ModelProvider`**：LLM 模型提供商。

## 5.2 流水线入口 — `Flux<ServerSentEvent<String>>`

```java
@Override
public Flux<ServerSentEvent<String>> execute(ChatContext context) {
```

- **`Flux`**：Reactor 框架的响应式流，表示"一个会陆续产生 0 到 N 个元素的异步流"。对比 `List<String>`（一次性返回全部）和 `Flux<String>`（来一个给一个）。
- **`ServerSentEvent<String>`**：SSE（Server-Sent Events）事件对象，每个事件有 `event`（事件类型）和 `data`（数据）两个字段。前端收到的格式：

```
event: plan_start
data: Planning task decomposition

event: plan_complete
data: Planned 3 task(s)
```

## 5.3 共享可变状态

```java
long orchestrationStart = System.currentTimeMillis();  // 记录开始时间
ChatRequest request = context.getRequest();             // 请求对象
String sessionId = request.getSessionId();              // 会话 ID
String userMessage = request.getLastUserMessage();      // 用户最后一条消息

// 共享可变状态 — 流水线写，响应阶段读
final List<String> toolResults = new ArrayList<>();       // 工具执行结果列表
final AtomicInteger successCount = new AtomicInteger(0);  // 成功计数（原子操作）
final AtomicInteger failCount = new AtomicInteger(0);     // 失败计数
final List<TaskNode> nodes = new ArrayList<>();           // 任务节点列表
final AtomicReference<ReflectionReport> reportRef = new AtomicReference<>();  // 反思报告
final AtomicReference<Double> reflectScoreRef = new AtomicReference<>(0.0);   // 反思分数
final AtomicBoolean pipelineOk = new AtomicBoolean(false);  // 流水线是否成功
```

**为什么用 `AtomicInteger` 而不是 `int`？**

Java 闭包中引用的外部变量必须是 `final` 或 effectively final。`AtomicInteger` 本身是 `final` 的引用，但内部值可以变（通过 `incrementAndGet()`），这样就绕过了限制。

## 5.4 Stage 1：CONTEXT_BUILD — 调用 Memory 服务

```java
sink.next(sseEvent("context_build_start", "Loading session and retrieving memories"));

MemoryQuery memoryQuery = MemoryQuery.builder()    // Builder 模式构建查询
        .queryText(userMessage)                    // 用用户消息作为查询文本
        .topK(10)                                  // 返回最相关的前 10 条
        .build();                                  // 生成不可变对象
MemoryQueryResult memoryResult = memoryFeignClient.retrieve(memoryQuery);
// ↑ 远程调用！底层流程：
//   1. Nacos 查 lyclaw-memory-service → 192.168.1.6:8082
//   2. POST http://192.168.1.6:8082/api/memory/retrieve
//   3. Body: {"queryText":"用户说了什么","topK":10}
//   4. 响应反序列化为 MemoryQueryResult

int memoryHits = memoryResult != null ? memoryResult.getTotalHits() : 0;
sink.next(sseEvent("context_build_complete", "Loaded session, retrieved " + memoryHits + " memory entries"));
// 通过 SSE 告诉前端：上下文构建完成
```

## 5.5 Stage 2：INTERCEPT — 安全检查（纯本地）

```java
if (securityManager != null) {
    var approvalResult = securityManager.approve(context, "EXECUTE_CHAT");
    if (!approvalResult.isApproved()) {
        sink.next(sseEvent("intercept_blocked", "Security check denied: " + approvalResult.getReason()));
        sink.next(sseEvent("done", "{\"status\":\"blocked\"}"));
        sink.complete();   // ← 结束 SSE 流
        return;            // ← 提前退出
    }
}
if (contentFilter != null) {
    FilterResult filterResult = contentFilter.filter(userMessage, context);
    if (!filterResult.isPassed()) {
        sink.next(sseEvent("intercept_blocked", "Content filter blocked: " + filterResult.getReason()));
        sink.next(sseEvent("done", "{\"status\":\"blocked\"}"));
        sink.complete();
        return;
    }
}
```

**`sink.next(...)`**：向 SSE 流中发送一个事件。
**`sink.complete()`**：关闭流，表示没有更多事件了。安全检查不通过，流水线就在这里终止。

## 5.6 Stage 3：PLAN — 调用 Plan 服务

```java
sink.next(sseEvent("plan_start", "Planning task decomposition"));

PlanRequest planReq = PlanRequest.builder()
        .sessionId(sessionId)           // 会话 ID
        .userIntent(userMessage)        // 用户意图
        .strategy("default")            // 规划策略
        .context(Map.of(                // 额外上下文
                "sessionId", sessionId,
                "timestamp", System.currentTimeMillis()))
        .build();
Map<String, Object> planResult = planFeignClient.plan(planReq);
// ↑ 远程调用！POST /api/plan/plan → lyclaw-plan-service

// 解析返回的节点列表
@SuppressWarnings("unchecked")
List<Map<String, Object>> rawNodes = planResult != null && planResult.get("nodes") instanceof List
        ? (List<Map<String, Object>>) planResult.get("nodes")
        : Collections.emptyList();
// @SuppressWarnings("unchecked")：告诉编译器"我知道强转不安全，别警告"
// instanceof List：先检查类型再转换，安全

for (Map<String, Object> raw : rawNodes) {
    List<String> tools = raw.containsKey("requiredTools") && raw.get("requiredTools") instanceof List
            ? (List<String>) raw.get("requiredTools") : Collections.emptyList();
    List<String> deps = raw.containsKey("dependencies") && raw.get("dependencies") instanceof List
            ? (List<String>) raw.get("dependencies") : Collections.emptyList();
    nodes.add(new TaskNode(
            (String) raw.getOrDefault("nodeId", ""),
            (String) raw.getOrDefault("type", "EXECUTE"),
            (String) raw.getOrDefault("description", ""),
            tools,
            deps,
            raw.get("timeoutMs") instanceof Number
                    ? ((Number) raw.get("timeoutMs")).longValue() : 30000L));
}
```

**`raw.getOrDefault("nodeId", "")`**：如果 Map 里没有 `"nodeId"` 这个 key，就用默认值 `""`，避免 NPE。

## 5.7 Stage 4：EXECUTE — 调用 Action 服务

```java
for (int nodeIndex = 0; nodeIndex < nodes.size(); nodeIndex++) {
    TaskNode node = nodes.get(nodeIndex);

    ToolExecuteRequest toolReq = ToolExecuteRequest.builder()
            .toolName(node.getType())                   // 工具名 = 节点类型
            .args(Map.of(                               // 执行参数
                    "nodeId", node.getNodeId(),
                    "description", node.getDescription(),
                    "sessionId", sessionId))
            .sessionId(sessionId)
            .build();
    ToolResult result = actionFeignClient.executeTool(toolReq);
    // ↑ 远程调用！POST /api/action/execute-tool → lyclaw-action-service

    if (result != null && result.isSuccess()) {
        successCount.incrementAndGet();  // 原子地 +1（相当于 successCount++）
        String output = result.getOutput() != null ? result.getOutput() : "";
        toolResults.add(output);         // 收集结果，用于后续反思和响应
    } else {
        failCount.incrementAndGet();
        String error = result != null ? result.getErrorMessage() : "unknown error";
        toolResults.add("ERROR: " + error);
    }
}
```

如果有 3 个节点，就发 3 次 HTTP 请求到 Action 服务。

## 5.8 Stage 5：REFLECT — 调用 Reflect 服务

```java
String combinedOutput = String.join("\n", toolResults);  // 合并所有工具输出
ReflectRequest reflectReq = ReflectRequest.builder()
        .sessionId(sessionId)
        .output(combinedOutput.isEmpty() ? userMessage : combinedOutput)
        .context("Orchestration pipeline execution - " + nodes.size() + " tasks processed")
        .build();

// ↑ 远程调用！POST /api/reflect/reflect → lyclaw-reflect-service

```

```java
    bodyFlux = adapter.chatStream(llmRequest)  // OkHttp 调用 DeepSeek API，流式返回
            .map(line -> {
                String text = adapter.extractSsePlainText(line);

            .filter(Objects::nonNull);  // 过滤空事件
```

# 第六课：服务方 MemoryController — Feign 的接收端

文件：`lyclaw-memory/src/main/java/.../controller/MemoryController.java`

## 6.1 类级别注解

```java
@Slf4j          // ← Lombok：自动生成 private static final Logger log
@RestController // ← = @Controller + @ResponseBody
@RequestMapping("/api/memory")
public class MemoryController {
```

### `@Slf4j`

编译时自动生成：
```java
private static final org.slf4j.Logger log = org.slf4j.LoggerFactory.getLogger(MemoryController.class);
```

### `@RestController`

```java
@RestController = @Controller + @ResponseBody
```

- **`@Controller`**：告诉 Spring "这个类是 HTTP 请求处理器，注册到请求映射表"
- **`@ResponseBody`**：告诉 Spring "方法返回值直接序列化为 JSON 写入 HTTP Response Body，不要去找视图模板"

### `@RequestMapping("/api/memory")`

**路径前缀**，和 Feign 客户端的 `path = "/api/memory"` 完全对应。所有方法的路径都会自动加上此前缀：

```
@RequestMapping("/api/memory")
        +
@PostMapping("/retrieve")
        =
POST /api/memory/retrieve    ← 最终对外暴露的路径
```

## 6.2 Feign 接口 vs Controller — 两端对照

```
┌─── Feign 客户端（调用方） ───┐          ┌─── Controller（服务方） ───┐
│                               │          │                              │
│ @FeignClient(                 │          │ @RestController              │
│   name = "lyclaw-memory-      │          │ @RequestMapping(             │
│           service",           │          │   "/api/memory")             │
│   path = "/api/memory")       │          │                              │
│                               │          │                              │
│ @PostMapping("/retrieve")     │  HTTP    │ @PostMapping("/retrieve")    │
│ MemoryQueryResult retrieve(   │ ──────→  │ public MemoryQueryResult     │
│   @RequestBody MemoryQuery q) │  POST    │ retrieve(                    │
│                               │          │   @RequestBody MemoryQuery q)│
│                               │          │                              │
│ @PostMapping("/ingest")       │  HTTP    │ @PostMapping("/ingest")      │
│ Map<String,Object> ingest(    │ ──────→  │ public Map<String,Object>    │
│   @RequestBody PerceptionData,│  POST    │ ingest(                      │
│   @RequestParam String sid,   │          │   @RequestBody PerceptionData,│

│                               │          │                              │
```

### 铁律：两边方法签名必须完全一致

| 项目 | Feign 客户端 | Controller | 必须一致？ |
|------|-------------|-----------|----------|
| HTTP 方法 | `@PostMapping` | `@PostMapping` | ✅ 必须 |
| 路径 | `/retrieve` | `/retrieve` | ✅ 必须 |
| 返回值类型 | `MemoryQueryResult` | `MemoryQueryResult` | ✅ 必须 |
| `@RequestBody` 参数类型 | `MemoryQuery` | `MemoryQuery` | ✅ 必须 |
| `@RequestParam` 参数名 | `"sessionId"` | `"sessionId"` | ✅ 必须 |
| `@RequestParam` 默认值 | `defaultValue = "default"` | `defaultValue = "default"` | ✅ 必须 |
| **方法名** | `retrieve` | `retrieve` | ❌ 不需要 |

**方法名可以不同**，因为 Feign 只关心注解中的路径和参数映射，不关心 Java 方法名。但保持一致是好习惯。

## 6.3 `@PostMapping("/retrieve")` 详解

```java
@PostMapping("/retrieve")
public MemoryQueryResult retrieve(@RequestBody MemoryQuery query) {
    log.debug("Memory retrieve: topK={}, layers={}", query.getTopK(), query.getLayerFilter());
    return memorySystem.retrieve(query);
}
```

- **`@RequestBody MemoryQuery query`**：Spring 从 HTTP Body 读取 JSON，反序列化为 `MemoryQuery`。比如收到 `{"queryText":"你好","topK":10}`，Jackson 将其转为对象。
- **`log.debug("topK={}", 10)`**：SLF4J 占位符，`{}` 自动被参数替换。debug 级别日志，生产环境通常不输出。
- **`return memorySystem.retrieve(query)`**：委托给 MemorySystem 领域接口去真正执行检索。Controller 只是一个**薄薄的路由层**，不写业务逻辑。

## 6.4 `@RequestParam` 的三种形态

```java
@PostMapping("/ingest")
public Map<String, Object> ingest(
        @RequestBody PerceptionData data,                                    // 形态1：Body参数，必传
        @RequestParam String sessionId,                                      // 形态2：URL参数，必传
        @RequestParam(required = false, defaultValue = "default") String userId) {  // 形态3：URL参数，可选
```

**实际 HTTP 请求：**

```
POST /api/memory/ingest?sessionId=abc&userId=john

Spring 解析：
  sessionId = "abc"       (从 URL)
  userId    = "john"      (从 URL)
  data      = PerceptionData对象  (从 Body JSON)

如果没有 ?userId=john：
  sessionId = "abc"
  userId    = "default"   (使用默认值)
```

## 6.5 `var` 关键字

```java
var entry = memorySystem.ingestPerception(sessionId, data);
```

**`var`** 是 Java 10 的局部变量类型推断。编译器从 `ingestPerception` 的返回值自动推断类型。编译后等价于：

```java
MemoryEntry entry = memorySystem.ingestPerception(sessionId, data);
```

## 6.6 `Map.of()` — 不可变 Map

```java
return Map.of(
        "entryId", entry.getEntryId(),
        "layer", entry.getLayer().name(),
        "status", "ingested");
```

`Map.of(K1, V1, K2, V2, ...)` 是 Java 9 的工厂方法。返回的 Map 不可变，不能 `put` 或 `remove`。最多支持 10 个键值对。

## 6.7 `@GetMapping` — GET 请求

```java
@GetMapping("/stats")
public MemoryStats stats() {
    log.debug("Memory stats requested");
    return memorySystem.getStats();
}
```

`@GetMapping` 是 `@RequestMapping(method = RequestMethod.GET)` 的快捷写法。GET 请求没有 Body，`MemoryStats` 对象自动序列化为 JSON 返回。

## 6.8 Controller 的分层职责

```
HTTP 请求
   │
   ▼
┌─────────────────────────────────┐
│ MemoryController（路由层）        │
│ 1. 接收 HTTP 请求                │
│ 2. 参数解析（@RequestBody等）    │
│ 3. 委托给 MemorySystem（业务层） │
│ 4. 返回结果（自动序列化为 JSON） │
└────────────┬────────────────────┘
             │
             ▼
┌─────────────────────────────────┐
│ MemorySystem（领域接口）          │
│ 定义业务能力，不关心 HTTP        │
└────────────┬────────────────────┘
             │
             ▼
┌─────────────────────────────────┐
│ HybridMemoryRetriever 等实现     │
│ 真正的业务逻辑：向量检索、       │
│ 嵌入模型、倒排索引...            │
└─────────────────────────────────┘
```

**关键设计原则：Controller 不写业务逻辑。** 只做三件事：接收请求 → 委托业务层 → 返回结果。

# 第八课：Feign 配置详解

## 8.1 超时配置

文件：`lyclaw-orchestration/src/main/resources/application.yml`

```yaml
spring:
  cloud:
    openfeign:
      lazy-attributes-resolution: true
      client:
        config:
          default:
            connectTimeout: 5000
            readTimeout: 30000
```

**逐项解释：**

- **`connectTimeout: 5000`**：建立 TCP 连接的超时时间，单位毫秒。5 秒内连不上目标服务就报错。适合局域网内的微服务调用（网络很快）。

- **`readTimeout: 30000`**：等待响应的超时时间。连接建立成功后，30 秒内没收到响应就算超时。AI 任务有些可能耗时较长，所以设了 30 秒。

- **`lazy-attributes-resolution: true`**：延迟解析 Feign 客户端的属性（如 URL、超时）。开启后，`@FeignClient` 的配置在第一次真正调用时才解析，而不是启动时就解析。好处是启动更快，而且支持动态配置。

## 8.2 FeignReactiveConfig

文件：`lyclaw-orchestration/src/main/java/.../config/FeignReactiveConfig.java`

```java
@Configuration
public class FeignReactiveConfig {

    @Bean
    public HttpMessageConverters httpMessageConverters() {
        List<HttpMessageConverter<?>> converters = List.of(new MappingJackson2HttpMessageConverter());
        return new HttpMessageConverters(converters);
    }
}
```

**逐项解释：**

- **`@Configuration`**：Spring 配置类，里面的 `@Bean` 方法会被 Spring 管理。
- **`@Bean`**：把这个方法的返回值注册到 Spring 容器。
- **`HttpMessageConverters`**：消息转换器容器，Feign 用它来做 Java 对象 ↔ JSON 字符串的序列化/反序列化。
- **`MappingJackson2HttpMessageConverter`**：Jackson 库的转换器实现。Feign 发请求时把 `@RequestBody` 参数转成 JSON 字符串；收到响应时把 JSON 字符串转成返回值类型。
- **`List.of(...)`**：Java 9 的工厂方法，创建不可变 List。

**为什么需要这个配置？**

Spring Boot 3.x 中，如果你的项目引入了 WebFlux（响应式 Web），默认不会自动配置 `HttpMessageConverters` Bean。而 Feign 需要它来做 JSON 转换，所以手动提供一个。

## 8.3 Gateway 超时配置

文件：`lyclaw-gateway/src/main/resources/bootstrap.yml`

```yaml
spring:
  cloud:
    gateway:
      httpclient:
        response-timeout: 300s    # ← 300 秒！
```

Gateway 的响应超时设了 **300 秒（5 分钟）**，比 Feign 的 30 秒长得多。因为：

- Feign 的超时针对的是**单个微服务调用**（比如一次检索、一次工具执行）
- Gateway 的超时针对的是**整个请求链路**（从用户请求到 AI 回复完成）

整个 5 阶段流水线跑完可能要几十秒甚至几分钟，所以 Gateway 要给足够长的时间。

## 8.4 依赖关系

```xml
<!-- lyclaw-core/pom.xml：Feign 接口所在模块 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>

<!-- lyclaw-orchestration/pom.xml：Feign 被使用和执行 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
```

三个依赖协作：

1. **`spring-cloud-starter-openfeign`**：提供 `@FeignClient`、`@EnableFeignClients`、动态代理生成
2. **`spring-cloud-starter-loadbalancer`**：提供 `lb://` 协议解析和客户端负载均衡
3. **`spring-cloud-starter-alibaba-nacos-discovery`**：提供 Nacos 服务发现，让 LoadBalancer 知道有哪些实例可用

| 参数 | 含义 |
|------|------|
