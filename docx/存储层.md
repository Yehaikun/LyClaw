# LyClaw 存储层架构文档

## 一、模块分层

```
lyclaw-core/                          ← 接口和抽象层（被所有模块依赖）
├── repository/
│   └── FileRepository.java           ← 文件仓库接口（原 StorageEngine）
├── strategy/
│   └── FormatStrategy.java           ← 格式化策略接口
├── base/
│   ├── BaseDTO.java                  ← 实体基类（id, createdAt, updatedAt）
│   ├── BaseStorage.java              ← 存储模板类（组合 FileRepository + FormatStrategy）
│   └── BaseEngine.java               ← 引擎基类（dataDir）
└── support/
    └── AbstractFileEngine.java       ← 文件引擎支持类（ObjectMapper 配置）

lyclaw-storage/                        ← 实现层
├── engine/
│   └── LocalFileEngine.java          ← 实现 FileRepository，继承 AbstractFileEngine
├── strategy/
│   ├── JsonFormatStrategy.java       ← JSON 格式化策略
│   └── MarkdownFormatStrategy.java   ← Markdown 格式化策略
└── storage/
    ├── SessionStorage.java           ← 继承 BaseStorage<Session>
    ├── ConfigStorage.java            ← 继承 BaseStorage<ModelConfig>
    ├── CronStorage.java              ← 继承 BaseStorage<CronJob>
    └── MemoryStorage.java            ← 继承 BaseStorage<Memory>

lyclaw-common/                         ← 纯实体类
└── model/
    ├── Session.java
    ├── Message.java
    ├── ModelConfig.java
    ├── CronJob.java
    ├── Memory.java
    ├── ToolCall.java
    └── Usage.java
```

## 二、类继承关系

```
BaseDTO                          ← 所有实体的父类
├── Session
├── Message
├── ModelConfig
├── CronJob
├── Memory
├── ToolCall
└── Usage

BaseEngine                       ← 引擎抽象基类
└── AbstractFileEngine            ← 文件引擎支持类（封装 ObjectMapper）
    └── LocalFileEngine            ← 具体实现，implements FileRepository

BaseStorage<T>                    ← 存储模板类
├── SessionStorage extends BaseStorage<Session>
├── ConfigStorage extends BaseStorage<ModelConfig>
├── CronStorage extends BaseStorage<CronJob>
└── MemoryStorage extends BaseStorage<Memory>

FormatStrategy<T>                 ← 格式化策略接口
├── JsonFormatStrategy<T>         ← JSON 序列化/反序列化
└── MarkdownFormatStrategy        ← Markdown 文本处理

FileRepository                   ← 文件仓库接口
└── LocalFileEngine implements FileRepository
```

## 三、BaseStorage 模板方法设计

```
BaseStorage<T>
├── 构造函数：注入 FileRepository + subDir + FormatStrategy<T>
│
├── 公共方法（子类直接继承）
│   ├── save(T entity)          → formatStrategy.serialize() → repository.write()
│   ├── get(String id)          → repository.read() → formatStrategy.deserialize()
│   ├── exists(String id)       → repository.exists()
│   ├── delete(String id)       → repository.delete()
│   └── getAll()                → repository.listFiles(suffix) → 逐个 deserialize
│
├── 钩子方法（子类可选重写）
│   ├── beforeSave(T entity)    ← 保存前处理（如校验、自动生成字段）
│   └── afterSave(T entity)     ← 保存后处理（如日志）
│
└── 抽象方法（子类必须实现）
    ├── extractId(T entity)     ← 从实体提取文件标识
    └── getEntityClass()        ← 返回实体类 Class 对象
```


**对应实体对象**（序列化前）：

```json
{
  "id": "global",
  "content": "## 用户偏好\n- 喜欢用 Java，代码风格偏好 Builder 模式\n- 希望所有响应都有详细注释\n\n## 项目信息\n- 当前项目：电商用户认证系统\n- 技术栈：Spring Boot 3 + MyBatis Plus\n- 数据库：MySQL 8.0\n\n## 其他\n- 记住这个",

  "createdAt": "2026-04-24T12:00:00",
  "updatedAt": "2026-04-26T14:30:00"
}
```

**注意**：Memory 使用 `MarkdownFormatStrategy`，文件后缀为 `.md`，存储的是 `content` 字段的原始 Markdown 文本，不包含其他元数据字段。

## 五、FormatStrategy 策略扩展

| 策略 | 后缀 | 适用实体 | 序列化方式 |
|------|------|----------|-----------|
| `JsonFormatStrategy<T>` | `.json` | Session、CronJob、ModelConfig 等 | Jackson ObjectMapper |
| `MarkdownFormatStrategy` | `.md` | Memory | 直接读写 content 字段 |

### 扩展新格式步骤

1. 实现 `FormatStrategy<T>` 接口
2. 放入 `lyclaw-storage/strategy/` 包
3. 对应的 `BaseStorage<T>` 子类构造函数传入新策略

```java
// 示例：未来扩展 YAML 格式
@Component
public class ConfigYamlStorage extends BaseStorage<ModelConfig> {
    public ConfigYamlStorage(FileRepository repository) {
        super(repository, "configs", new YamlFormatStrategy<>());
    }
}
```
